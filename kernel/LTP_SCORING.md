# LTP 评分说明

## 背景

LTP（Linux Test Project）测试用例的原始得分（raw score）范围为 **0 ~ 10000**。
为了让 LTP 在总评中的占比可控、并让不同水平学生的得分尽量平滑，需要将原始分映射到一个固定区间。

设计目标：

- **封顶 500 分**：LTP 对总分的贡献最多 500 分。
- **平滑过渡**：得分随原始分连续变化，没有阶梯式跳变。
- **照顾低分段**：低分阶段每多通过一个用例带来的收益更高（凹函数曲线），让起步阶段的学生更容易拿到分数。

## 映射公式

采用对数曲线：

```
final = 500 * log10(1 + 9 * raw / 10000)
```

其中：

- `raw` 为 LTP 原始得分，使用前会被裁剪到 `[0, 10000]` 区间。
- `final` 为计入总分的 LTP 得分，范围 `[0, 500]`。

边界行为：

- `raw = 0`     → `final = 0`
- `raw = 10000` → `final = 500`
- `raw > 10000` → 裁剪为 10000，`final = 500`（不会超出封顶）
- `raw < 0`     → 裁剪为 0，`final = 0`

## 曲线特性

该曲线为**凹函数**，斜率在低分段最大、随原始分增大而递减。
即：分数越低，多通过用例所获得的“性价比”越高，从而照顾起步阶段的学生。

| 原始分 raw | 最终分 final |
|----------:|------------:|
|       100 |        18.7 |
|       500 |        80.7 |
|      1000 |       139.4 |
|      2500 |       255.9 |
|      5000 |       370.2 |
|      7500 |       444.7 |
|     10000 |       500.0 |
|     12000 |  500.0（封顶）|

## 代码位置

实现位于 `kernel/postwork.py` 的 `postwork()` 函数中，对组名包含 `ltp` 的测试组单独处理：

```python
if "ltp" in group.lower():
    raw = max(0.0, min(s['#TOTAL'], 10000.0))
    score += 500.0 * math.log10(1 + 9 * raw / 10000.0)
else:
    score += s['#TOTAL']
```

## 调参说明

如需调整曲线形状（在保持封顶 500、过零点的前提下），可替换映射函数：

- **加大对低分段的倾斜**：使用底数更大的对数，如 `log_b`，b 越大低分段越陡。
  通用形式：`final = 500 * log(1 + (b-1) * raw/10000) / log(b)`，当前实现取 `b = 10`。
- **改用幂函数（倾斜更温和）**：`final = 500 * (raw/10000) ** p`，其中 `0 < p < 1`，`p` 越小越照顾低分段（例如 `p = 0.5` 为平方根曲线）。

无论选用哪种，都需保证函数在 `[0, 10000]` 上单调递增、过 `(0, 0)` 与 `(10000, 500)` 两点，并对入参做 `[0, 10000]` 裁剪以防越界。
